Aplicação no Projeto: Interface Segregation

No SmartGreen, cada parte do sistema depende apenas da interface que realmente utiliza.

SOLID - ISP

Contexto do Projeto

  • O projeto separa os contratos de comunicação com a API por responsabilidade específica.
  • O login depende de ClienteEntradaAutenticacao, que possui apenas o método de entrada.
  • O cadastro depende de ClienteCadastroAutenticacao, que possui apenas o método de cadastro.
  • O painel separa consulta e simulação com ClienteConsultaTrafego e ClienteSimulacaoTrafego.
  • Nenhum trecho do front-end precisa depender de um contrato maior do que sua necessidade.
  • Isso reduz acoplamento e facilita manutenção, testes e evolução.

Exemplo no Código

Autenticação segregada
interface ClienteEntradaAutenticacao {
  entrar(): Promise<RespostaAutenticacao>;
}

interface ClienteCadastroAutenticacao {
  cadastrar(): Promise<RespostaAutenticacao>;
}
Tráfego segregado
interface ClienteConsultaTrafego {
  obterVisaoGeral(): Promise<VisaoSistema>;
}

interface ClienteSimulacaoTrafego {
  simular(): Promise<VisaoSistema>;
}
Frase para apresentar: cada fluxo conhece apenas o contrato que precisa. Entrar, cadastrar, consultar o painel e simular o tráfego ficaram em interfaces menores e independentes.
